# MLP 组件与动效实现参考

本文件提供可选实现方法；设计质量要求统一归 visual-standard.md。src/prototype-ui/components/index.jsx、patterns.css 和 tokens.css 是工具箱及默认值，可以修改、扩展或替换。无需登记自定义组件或服从组件外观白名单。

## 视觉组件按角色复用

重复出现的按钮、标签、素材槽和列表行可共享基础实现，并通过选中、就绪、加载、禁用等状态表达差异。专用大预览、工具栏和模式面板可保持自己的形态。图标按钮和文本按钮不必使用相同尺寸。

可选择 PageScaffold / ScrollablePageWithActions / ActionBar，也可自行组织滚动与操作区。浮动动作需要留白时，让留白与实际占用联动；输入高度改变后重新布局。不要为了套用工具箱改变产品信息结构。

## 将关联UI从同一状态派生

参考HTML的 MODES + setMode 思路：一个模式配置提供标签、预览说明、输入需求和动作类型。事件只更新当前选择，渲染逻辑从它更新相关区域。

在React中用state及派生值，在原生HTML中用统一render函数即可。不要分别维护互不相干的DOM active类、按钮文案和业务模式。初始化也调用同一套派生逻辑，避免“高亮A、实际执行B”。模式切换时按任务决定是否保留输入与素材。

## 按压、选中与就绪

只为需要变化的属性声明transition。按压缩放作用于视觉元素，不改变周围布局；选中态可同时调整背景、边界和文字。focus-visible提供与触摸反馈协调的键盘焦点样式。

就绪外观由真实校验结果驱动。不能提交时使用实际disabled或实现对应校验行为，不能只把按钮变暗。加载按钮保持位置稳定，完成态恢复可操作表现。

## 展开、切页与浮层

折叠区可沿用参考HTML的Grid方案：外层grid-template-rows在0fr与1fr之间变化，内层min-height: 0和overflow: hidden。折叠时同时管理内容的可聚焦性，展开按钮同步aria-expanded。

页面切换可保留旧页面完成淡出，或按框架生命周期挂载新页面做入场动画。隐藏页面应退出交互与键盘焦点；仅opacity: 0和pointer-events: none不够。

Sheet / Modal 使用明确的打开、进入、打开完成、退出、关闭生命周期，或采用等价的CSS动画方案。进入时保证初始样式能被浏览器绘制，退出动画结束后才隐藏或卸载。不要依赖父级从display: none切到flex，同时改transform就必然发生过渡。

打开浮层时管理焦点及底层交互，关闭后归还焦点；在手机容器内处理遮罩层级。减少动态效果时立即结束相应生命周期，不能因没有transitionend而卡住。

渐变或图片切换若需要平滑效果，可用两层背景交叉淡入；不要假设transition: background会让任意渐变连续插值。

## 连续的任务反馈

以idle / running / success / error等实际任务阶段驱动反馈；按产品需要增加cancelled。running阶段保持等待反馈，结果出现后才开始结果提示的自动消失计时。

开始新任务或离开组件时清理旧计时器；异步结果也可通过任务标识丢弃过期响应。重复操作可以禁用、合并或取消重启，由产品决定，但不叠加多组相互覆盖的进度。

普通提示、等待和成功使用对应表现；不要让成功Toast继续旋转。优先使用可重复的模拟时序方便评审，不将虚构进度伪装成真实服务状态。

## 集成边界

这里的实现建议不要求引入动画库。原生CSS与现有框架足以实现多数反馈；复杂场景再选择适当工具。维护已有稳定元素ID，避免过渡层捕获标注点击，截图和人工标注的边界由 template-contract.md 管理。
