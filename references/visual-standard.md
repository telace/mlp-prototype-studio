# MLP 原型视觉与交互规范

本文件替换之前的原型设计约束，是原型设计质量的唯一规范来源。依据用户提供的 pixverse-ui-prototype.html 源码提炼（2026-10-26）；下文已包含必要方法，不依赖原文件或其内嵌素材。CSS声明说明实现意图，不代表原案例已通过浏览器动效验收。

目标：页面具有清晰的视觉层次、经过设计的控件细节、轻量而有意义的动效，以及连贯的操作反馈。产品内容、功能、页面数量、布局、配色和组件实现由当前PRD与用户方向决定。

## 1. 视觉语言：层次统一，形态按角色变化

- 区分页面底色、内容表面、浮层和强调区域。通过明度、透明度、细描边或适量阴影建立层次，不给所有区域相同重量。
- 让高对比服务于主操作、当前选中或关键结果；次要操作保持较弱。品牌色、渐变、光晕和模糊可用于焦点或层次，是否使用由项目决定。
- 文字分清标题、正文、辅助信息。利用字号、字重、颜色与间距共同建立层级；辅助文字变弱后仍需可读。表单和按钮使用项目字体，中文与长文本按实际阅读效果调整。
- 同角色的控件保持一致，不同角色可使用不同形态：大预览圆角更舒展，内容卡片紧凑，筛选标签可为胶囊，独立图标动作可为圆形。无需把它们做成相同高度或圆角。
- 图标采用协调的线条、视觉重量和光学对齐；图标与文字留出呼吸空间。纯图标操作有可理解的名称。
- 保持页面边距、区域间距和内容内边距的节奏；图片可通栏，横向选择可露出下一项，信息密度服从任务。
- 图片文字叠放时，以局部遮罩、底板或其他方式保证可读。内容可以使用真实素材或有意设计的占位，不因缺少素材把所有区域机械地做成相同色块。

参考HTML中的比例示例，仅用于理解设计关系，不是允许值集合：

| 部位 | 参考实现 | 采用时的判断 |
|---|---|---|
| 暗色层次 | #07040d底色、#0f0a1c面板、#151026卡片 | 复用层次关系；项目可以采用浅色或其他色系 |
| 描边 | 白色透明度约8%，强调边界约16% | 随背景调整，让边界可辨而不抢内容 |
| 文字 | 26px页标题、20px预览标题、15px区块标题、约12–13px控件文字 | 观察主次比例；不要直接把紧凑英文尺寸套给中文正文 |
| 间距 | 20px页面边距，8–12px常见元素间距 | 按内容密度与实际画布调整 |
| 圆角 | 26px大预览、18px卡片、16px素材槽、胶囊标签 | 统一角色关系，不统一所有形状 |
| 重点操作 | 白底深色按钮；渐变创作入口 | 根据项目底色选出足够醒目的主操作 |

无需照搬PixVerse品牌、Manrope字体、紫粉主题或参考文件中的素材。MLP工作台的画布和截图坐标仍由 template-contract.md 管理。

## 2. 动效：对操作作出轻量响应

为实际存在的交互选择适当反馈。按下、选中、展开、切页、等待、完成各有目的；不为了展示动画而让内容持续晃动或让用户等待动画结束才能继续操作。

| 场景 | 参考HTML的做法 | 可采用的体验 |
|---|---|---|
| 按压 | 小控件缩放约0.92–0.96，卡片约0.98 | 短促确认按下，释放恢复，周围布局不跟着挤动 |
| 选中与就绪 | 约200–250ms颜色、描边或阴影变化 | 当前选项和可执行操作自然变得明确 |
| 页面切换 | 280ms透明度过渡，缩放0.985到1 | 轻量切换；不适合缩放的页面可只淡入或使用方向转场 |
| 展开收起 | 280ms Grid行高过渡，箭头同步旋转 | 内容和指示方向同步；内部内容不被突然切断 |
| Toast | 300ms淡入并上移16px | 反馈出现时不挤压正文，也不遮住关键操作 |
| Sheet / Modal | 背景变暗，面板短距离进入 | 开关过程完整，关闭后恢复底层交互 |
| 等待与完成 | 加载指示、进度变化、完成反馈 | 等待持续可见，完成后停止加载并给出下一步 |

这些数值是起点，允许依据内容、平台与性能调整。优先动画化 opacity 和 transform；展开内容需要高度变化时可选Grid行高等方案。尊重 prefers-reduced-motion，减少动态时保留清晰的静态反馈。实现注意事项见 component-patterns.md。

## 3. 状态联动：一次动作对应一组一致变化

- 一个选择状态驱动关联的选中样式、标题、预览、字段或素材槽、主操作及反馈。初始化与后续切换采用同一套状态派生逻辑。
- 输入内容变化时同步处理输入框高度、校验提示、提交条件和按钮外观。按钮看起来不可用时，实际行为也应匹配；若允许点击解释原因，应明确表现为可交互。
- 进入下一步时携带用户选择或已输入的内容，例如选择模板后带入创作页。返回后的保留或重置行为符合当前任务。
- 主要演示路径上的控件有明确结果：切换、展开、更新内容、提交或提示。次要未实现能力可提供简洁反馈；不把所有操作都替换成同一个Toast。
- 模拟任务可自动推进已定义状态。等待反馈覆盖整个任务，完成或失败时结束加载表现；重复提交、取消、离开页面不能收到上一次任务的过期反馈。
- 模拟能力在原型说明中标明。预览反馈使用产品用户能理解的文案，不把调试信息或“实现框架”说明塞进产品操作流。

## 4. 滚动内容与操作区域协同

根据任务选择行内、吸底、悬浮或固定操作。固定操作放在手机画布内；正文滚动、底部导航、浮层和提示分别有清楚的层级。

底部空间应与实际操作区域高度配合，考虑文字换行、输入增长和安全区；可采用布局分区、共享尺寸变量或测量。不要直接复制参考HTML的76px导航或200px留白作为所有页面的公式。滚动到最后仍能读完并操作末尾内容，打开Sheet或键盘后关键动作可达。

半透明背景、模糊和边缘渐变可让浮动工具与正文衔接自然，但文字必须清楚；这些处理是选项，不是必需装饰。

## 5. 交付时如何判断

查看本次改动的实际页面，检查主次层级、长文本、选中与不可用状态、滚动末尾和浮层遮挡。涉及交互时走一条主要路径，观察初始状态、操作过程、关联区域更新及最终反馈；涉及计时任务时再检查重复触发或离开页面。

动效检查覆盖开始、过程和结束，不能仅凭CSS存在transition就声称流畅。截图适合检查静态细节，点击体验用于确认交互。无法运行时明确说明未验证的部分。

这里只要求有依据的设计与交互质量，不按固定字号、卡片数量、强调色数量、CSS属性/数量或组件名单拦截设计。技术检查仍保护PRD、工作台、标注、截图与可运行性。
